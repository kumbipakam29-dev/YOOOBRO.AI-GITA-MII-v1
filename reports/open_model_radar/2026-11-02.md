## Free hosted options versus self-hosting

### Current $0 hosted routes

OpenRouter currently lists these useful free routes:

- `cohere/north-mini-code:free` — text/code, 256K, tool calls; 99.83% displayed 72-hour availability at scan time.
- `xingchen-agi/xing4.0-29b-a4b:free` — text/tool use, 256K; 99.75% displayed 72-hour availability.
- `nvidia/nemotron-3.5-super-vl:free` — visual/document/video agent, 1M; 97.96% displayed 72-hour availability, but the endpoint explicitly forbids confidential data and personal media such as faces/voices.
- `google/gemma-4-26b-a4b-it:free` — general reasoning/vision; shared, rate-limited endpoint.
- `dots-studio/dots-3-note-preview:free` — 512K; announced retirement on 2026-12-31.
- `recursive/flint-v1.0:free` — avoid for any workflow requiring reliability; only 3.32% displayed 72-hour availability at scan time.

OpenRouter free routes are rate-limited (the current docs describe a 20 RPM / 50 requests per day class limit for free users; limits and model availability can change). A free route is a hosted inference service, not a promise that the weights are locally runnable at zero cost. Provider data handling is separate from the model's weight license. Use synthetic/public inputs only until each provider's retention, training and privacy terms are approved.

Hugging Face's Inference Providers pricing page currently shows **$0 included monthly credits for Free users**. Do not count on HF as free hosted inference.

### Self-host cost examples

Google's official Gemma 4 memory table estimates:

- Gemma 4 E4B: 17.9GB BF16, 8.9GB SFP8, 4.5GB Q4_0; LiteRT-LM mobile profile about 2.5GB.
- Gemma 4 26B A4B: 57.7GB BF16, 28.8GB SFP8, 14.4GB Q4_0.

Those are weight/runtime-load estimates, not complete long-context memory; KV cache adds more. Qwen3.8-27B's BF16 repository is about 55.6GB. DeepSeek V4.1 Flash is about 510GB, GLM about 328GB, MiniMax about 252GB, and Kimi K3 about 1.56TB of repository storage.

Modal's current Starter page advertises $30 monthly compute credits. Listed rates include A100 80GB at about $2.50/GPU-hour and H100 80GB at about $3.95/GPU-hour. If the full $30 credit is available to the account, that is roughly 12 A100-hours or 7.6 H100-hours before storage, CPU, network and other charges. It is a limited trial allowance, not free permanent hosting. Large multi-GPU models can consume the credit in well under an hour.

## YOOOBRO agent mapping

- **Conversation / on-device fallback:** Gemma 4 E4B; preserve the separate bear TTS/voice identity pipeline.
- **GitHub coding, bug fixing, test writing:** North Mini Code first; Xing4.0 second. Keep tools read-only initially and only allow changes on a review branch/PR.
- **Vision, documents, screenshots, video:** Nemotron 3.5 Super VL for public/synthetic tests only; local NVFP4 deployment is a later hardware project.
- **Safety and Kids Safe:** Nemotron 3.5 Content Safety plus deterministic policy checks, consent state, age-mode rules and human escalation. Never let a classifier alone approve a response.
- **Long-context research / frontier reasoning:** DeepSeek, GLM, MiniMax, Kimi and Qwen Flash Next stay research-only until a real multi-GPU budget and reproducible test harness exist.
- **RAG:** add multilingual embedding and reranking specialists as separate registry roles; do not use a generative model's similarity intuition as the retrieval score.

## State separation (mandatory)

- **DISCOVERED:** model ID found upstream.
- **METADATA VERIFIED:** official card, exact upstream revision, license metadata, modalities/context and published hardware notes checked.
- **CONFIGURED:** provider/runtime adapter, endpoint, auth and pinned revision are set in YOOOBRO.
- **TESTED:** the exact checkpoint was actually executed on named hardware/runtime and logs, hashes, latency, quality and failures were recorded.
- **ACTIVE:** production route approved after privacy, license, safety, reliability and fallback checks.

At this scan, the 15 registry entries are **DISCOVERED + METADATA VERIFIED only**. None is downloaded, configured, tested, trained by MIi, or active in YOOOBRO. The current research repository's successful CI/reality-validation runs cover synthetic baseline tasks and bounded local checks, not these frontier checkpoints.

## Next engineering work

1. Add a provider-neutral OpenAI-compatible adapter with exact model ID + full revision pinning, capability metadata and per-route privacy labels.
2. Implement the first three smoke tests using public/synthetic inputs: Gemma 4 E4B (mobile), North Mini Code (coding), and Xing4.0 (agent planning).
3. Reuse the simulation-to-reality gate: identical task IDs, inputs, seeds and acceptance criteria; record actual output, exit code, latency, token counts, tool calls, test result and artifact hashes. A simulation pass must never set a real-pass flag.
4. Build a 100-prompt Hindi/Hinglish/Gujarati set, 50 tool-use tasks, 25 safety/roast boundary cases, 20 image/scene tests and 10 offline latency/thermal tests.
5. Keep free hosted routes on public/synthetic data only; do not send camera frames, face images, voice recordings, private GitHub code or secrets to the NVIDIA free endpoint.
6. Only after those tests should any candidate move from VERIFIED to CONFIGURED, TESTED and eventually ACTIVE.
